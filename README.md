# agentic-slop toolkit for Claude Code

One plugin, `slopify`, provides seven workflows and three skills for engineering and library work. Each workflow script is the only orchestrator of its run: it gathers evidence through scouts, takes judgement from advisors, produces through `writer` and `coder`, validates through lenses and `qa`, and acts on the board and forge only through `pusher`.

## Agents

Every agent is a leaf that dispatches nothing but the built-in `Explore`, and pins its model and effort in its definition; workflows never override them.

Scouts, lenses, and advisors have one task each and no return format; the workflow passes their schema. Dispatch names are plugin-qualified, such as `slopify:scout-code`.

## Fresh verdicts

`qa`, `library-clerk`, `auditor`, and every lens carry the same Report-only contract: judge only work you didn't produce or judge before, and only the revision the brief names; change nothing; report a check that couldn't run as unverified; pass only when every required check ran and nothing blocking remains. Every verdict is a new agent dispatch made after the revision it judges exists, never a continuation of a producer or an earlier validator. Validators never repair the candidate; the producer fixes from the findings, and new validators judge the new revision.

Each gate allows three failures per run. A failure is a `fail` verdict, an `unverified` verdict whose missing prerequisite a producer could supply, or a producer reporting the approach unworkable.

## Blocked results and reruns

When a workflow can't proceed — a gate runs out of failures, a decision is open, the story is unbuildable as stated, or a prerequisite is missing — it returns `blocked` with the step, what it needs, the steps completed, the checkpoints that exist, and the attempts. A story blocker goes back through `shape`; the deliver workflows never rewrite a story or a criterion's meaning.

A rerun is a new run with fresh budgets:

- **In the same session**, rerun with the same args plus `answers` for each need, and pass `resumeFromRunId`. Steps before the one that raised the need replay from the cache.
- **Across sessions, or after the story or repository changed**, rerun without resume. Each run starts by asking `scout-checkpoint` for its durable checkpoints — the branch and worktree, the committed spec, ledger lines, the PR, a draft, a findings document, a filed card, or a reproduction directory — and skips every step a current checkpoint proves complete.

## Ledger

`deliver-story`, `deliver-bugfix`, and `review-pr` keep one append-only ledger per story worktree at `.tmp/ledger.md`. `pusher` is its only writer: every `pusher` dispatch appends the lines for the step it makes durable, so no dispatch exists just to write the ledger. It records each run, `done spec`, `done implement`, and `done publish`, and each review round's trigger and outcome. A checkpoint counts only while the chain before it is current: a revised spec re-runs implementation, validation, and publishing, and a changed story re-runs everything from the spec. `shape`, `deliver-spike`, and `reproduce-bug` need no ledger; their checkpoints are their artifacts.

## Review loop

Once the PR opens, `publish` fires the review the forge declaration names (unless opening fires it), and `review-pr` takes over. Each round, `watcher` waits for the review, one bounded dispatch at a time; one `lens-finding` per finding sorts it into a defect, a non-issue with its reason, or unverified. Only confirmed defects are fixed: `coder` takes code and `writer` takes spec and documentation, a fresh `qa` validates, and `pusher` commits, pushes, updates the PR, and fires the review again. After at most three rounds the final review is sorted and reported unfixed. The loop also ends when no defect remains, or when the review fails, times out, or isn't declared. Invoking `review-pr` with a PR and its findings enters the same loop without waiting.

## Project authority

Project authority lives in [`docs/BOARD.md`](docs/BOARD.md), [`docs/FORGE.md`](docs/FORGE.md), and `library/_meta/librarian.md` in the target project. Invoking a deliver workflow or `review-pr` authorizes the story branch and worktree, attributable commits, a push once the gates pass, opening or updating the task's PR, and the declared review trigger, re-fired after each verified push. `reproduce-bug` authorizes filing one `Bug` card. `deliver-spike` authorizes creating, and then deleting, its own unpushed prototype branch and worktree; its findings document stays uncommitted. `shape` files or updates the story card only when its args set `file: true`. No workflow merges or releases. Every workflow and skill assumes the project is bootstrapped; rerun `bootstrap` to verify and fix the setup.

## Install

```bash
claude plugin marketplace add ca77y/agentic-claude
claude plugin install slopify@agentic-slop
```

Run `/reload-plugins`, or start a new session, after installing or updating to load skills, workflows, and agents.

Every workflow runs only when invoked explicitly: as `/slopify:<name>`, such as `/slopify:deliver-story SMR-12`, or when you ask to run the slopify `<name>` workflow. This includes `shape`, which no longer runs when you merely describe shaping work. The skills run by qualified name, such as `/slopify:ask`, or when you describe matching work.

The workflows dispatch many background agents that run git, tests, and the forge CLI, so they are designed for auto-approve or bypass permission mode; in default mode those agents' permission prompts arrive while the workflow is waiting.
