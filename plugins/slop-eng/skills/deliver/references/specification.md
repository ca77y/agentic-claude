# Specification

A delivery spec is proportionate and covers:

- the problem and intended outcome, scope, and exclusions;
- the intended approach, constraints, and dependencies;
- observable acceptance criteria, one behavior each, and how each will be verified;
- when the work splits into independent parts, the tasks it breaks into.

For card-backed work the card is the acceptance source. A criterion that is wrong or ambiguous is corrected in the spec with the original wording and the reason beside it; the card itself changes only as `docs/BOARD.md` allows. The spec stays where it was written; whether it is later kept, folded into other documents, or removed is the user's decision.
