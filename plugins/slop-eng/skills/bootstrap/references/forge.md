# Forge declaration authoring

Read only for requested creation or repair of `docs/FORGE.md`. Use [the forge template](../resources/FORGE.md) as a field guide. Replace authoring prompts with supported facts or explicit unavailable operations. Infer repository/remotes and branch conventions from local repository metadata, ignore rules, commits, existing documentation, and supplied context. Ask for unresolved destinations or authority. Never expose credentials or invent authenticated access.

Record repository and permitted remote destinations, target branch protection, branch derivation and existing-workspace recovery, worktree/ignore conventions, commit style, local checkpoint versus validated push behavior, change-artifact title/body and unused metadata, real returned URL usage, review triggers, and user-owned publication decisions. Cite board-owned identity facts rather than duplicating them. Record the project's temp folder, defaulting to `.tmp/` relative to the project root, and its matching ignore rule. Preserve an existing configured path unless the user requests a change. Workflow ledgers live in `<temp-folder>/ledgers/`; exclude them and required evidence from scratch cleanup, including after completion.

Use operation conditions without custom-agent/skill names, invocation commands, model policy, or orchestration sequences. A commit/PR endpoint or explicit isolation request may authorize workspace preparation; ordinary local changes do not imply publication. Configuration is not execution authorization. Preserve restrictions on merge, cleanup, second changes, force push, pushed-history rewrite, refs, releases, and destinations.

Explicit no forge is a valid complete choice. Record repository/local commit conventions and any separately authorized remote operations, while marking hosted change and review operations unavailable. Do not treat an unresolved forge choice as no forge. Fresh audit uses read-only evidence only; no test branch, commit, PR, or comment is created to prove a binding.
