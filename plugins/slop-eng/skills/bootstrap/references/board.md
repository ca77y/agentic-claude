# Board declaration authoring

Read only for requested creation or repair of `docs/BOARD.md`. Use [the board template](../resources/BOARD.md) as a field guide, replacing every authoring prompt with established facts, explicit unavailable operations, or unresolved choices for the setup spec. Do not publish guessed bindings. If policy already exists elsewhere, point to it and fill missing fields instead of maintaining competing rules.

Read project tracker evidence and supplied choices. Record board identity/project/team, tool or CLI identifiers and access mechanism without credentials, locate/read/search and each mutation binding, card schema and acceptance format, full status vocabulary, legal transitions with source-state preconditions, visibility destination, and user-owned decisions.

Write operation-based conditions, without custom-agent/skill names, invocation commands, model policy, or orchestration sequences. Configuration never authorizes execution. Describe the actual request needed for card creation, content refinement, attaching a returned PR URL, and comments. Do not infer default mutation permission from an omitted binding. Preserve readiness and terminal gates and prohibit acceptance rewrites to match implementation.

An explicit no-board choice is a complete declaration: state no tracker, no card operations, and where authorized local acceptance material lives. An unresolved choice is a question, not permission to choose no board. The fresh auditor uses supplied facts and available read-only evidence; setup never probes mutations.
