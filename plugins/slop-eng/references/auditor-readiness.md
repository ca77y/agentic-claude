# Specification readiness

Inspect requirements, scope, current repository constraints, supporting sources, proposed approach, and observable acceptance criteria. Judge feasibility, consistency, product fit, and whether the evidence plan can establish acceptance. Independently challenge high-risk or uncertain designs; distinguish missing material decisions from routine implementation choices.

Spec drafting is permitted before this gate. For setup, evaluate supplied project facts and templates without requiring the declarations being created. Report blocking ambiguity before implementation; a passing verdict identifies this exact revision.

For execution specs, require an overall integer complexity from 1 to 10 and rationale, plus a score and rationale for every task (at least one identified task). Assess whether the scores fit the supplied scope, uncertainty, coupling and consequences; do not infer all task scores from the overall score or mandate a fixed document template. A spec readiness task is distinct from its implementation children; fresh validation of a reused spec is evidence-only and its historical author does not establish a child tier. Missing scores block readiness for delivery, including reused specs. Proposal-only work and trivial work without an execution spec retain their existing exemptions.
