# Document and acceptance audit

Compare the exact candidate with requirements and validated scope. Inspect relevant facts, citations, local links, consumers, and package resources. Run available documentation/package validators and actual-resource checks when in scope. Preserve the candidate; recommendations are for its production owner.

For setup, assess declarations against supplied repository facts, requested choices, and existing restrictions. Use read-only evidence; never probe an external write, branch, commit, or PR to validate configuration. Missing access limits the affected claim. One adequate final verdict suffices; request separate executable QA only for evidence beyond this scope.

## False-claim correction acceptance

When the candidate repairs a documentation-accuracy finding, evaluate the claim across the entire candidate change, including prose, tests, identifiers, comments, tables, and source documentation. Establish the exact final snapshot and compare its inventory with the supplied baseline and attributable committed, staged, unstaged, untracked, renamed, and deleted paths; unrelated work must be explicitly excluded. Missing inventory or unreadable evidence limits acceptance rather than disappearing from scope.

Grade the supplied evidence item by item against source, not by the appearance of the rewrite. Check every sentence in the affected passage, including connective and summary sentences, for a supporting `path:line` and an observed value or behavior that actually supports it. Separately grade every restatement disposition in sibling paragraphs, related tables, and source docstrings. Confirm removed claims are absent and every retained restatement carries the same material qualifier when the correction qualifies the claim.

Inspect and reproduce the final candidate search for distinctive terms and meaningful negations across every candidate file without an extension filter. Check completeness and the keep/change disposition and reason for every hit, including test names, identifiers, and inline comments. Inspect context for missed restatements, incomplete search terms, contradictory assertions, stale evidence, and unintegrated change dispositions. A zero-hit report needs a recorded search and plausible terms. Deleted paths must be accounted for; unreadable files are unresolved evidence gaps.

Report each sentence, restatement, and search disposition as supported, contradicted, or unverified with source locations and reasons. Missing support, omitted hits/restatements, inconsistent qualifiers, or a stale/incomplete record blocks the affected acceptance. Return findings to the production owner without editing; corrections require a fresh validator under the core contract.
