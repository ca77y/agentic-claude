# Forge operations

Read `docs/FORGE.md` for the remote and push destinations, the target branch and its protection, the branch and worktree naming, the commit convention, the pull-request bindings, the review trigger, and the restrictions. Resolve any relative path in the declaration against the main checkout root, the parent of `git rev-parse --path-format=absolute --git-common-dir`, never against a worktree. An operation the declaration doesn't bind, or that a restriction forbids without the brief carrying the user's request that lifts it, is unmet; the one exception is a local prototype branch, below.

- **Branch and worktree.** Create the worktree with the declared command and name from the main checkout root, or recover it with the declared command when the branch already exists. Never commit to, or check out, the target branch in a worktree.
- **Branch only.** When the brief says the user asked for a branch only, create no worktree: from the main checkout root, check out the declared branch, created from the target branch with `git checkout -b <branch> <target>` or recovered with `git checkout <branch>` when it exists, and report the main checkout root as the worktree. Never commit to the target branch.
- **Local prototype branch.** When the brief authorizes creating, or removing, its own local prototype branch and worktree that were never pushed, do so with the branch and worktree names the declaration's "Spike prototypes" line gives, and invent no names: when that line says none, create nothing and report it as the brief asks. Create with `git worktree add <path> -b <branch>` from the main checkout root, and remove with `git worktree remove <path>`, then `git branch -D <branch>`. Before removing, confirm the branch was never pushed: no declared push destination has it (`git ls-remote --heads <remote> <branch>` prints nothing) and it has no upstream. Refuse, as unmet, when it was ever pushed or when a declared restriction forbids the operation without the brief carrying the user's request that lifts it. When the brief asks for branches only, check the prototype branch out in the main checkout with `git checkout -b <branch> <target>` instead of adding a worktree, and remove it by discarding its changes (`git checkout -- .` and `git clean -fd`, which keeps ignored files), checking out the branch the brief names, and then `git branch -D <branch>`. Remove no other worktree and delete no other branch.
- **Commit.** Stage exactly the paths the brief lists, by name (`git -C <worktree> add -- <paths>`), never everything and never with `-f`. Check that the staged set is exactly those paths before committing, and never commit a change the brief didn't list. Write the message in the declared commit convention. Report the new commit's sha.
- **Push** only to a declared destination, and only the branch the brief names, when the brief asks. A delivery pushes every round, even with something still flagged, so that every attempt stays in history. Never force-push or rewrite pushed history.
- **Pull request.** Read the branch's open PR through the read binding first. Open one only when none exists, as a draft when the brief says so; otherwise update it. Use the declared title, and the body the brief supplies. Mark it ready only when the brief says so. Report the PR URL or path.
- **Review trigger.** Fire it through the declared binding, unless the declaration says opening the PR fires it. Report the trigger time: the PR's creation time when opening fired it, otherwise the time the forge records for the trigger, or, when it records none, the time taken just before firing.
- **Delivery-start and PR-open card operations** follow `pusher-board.md`.
