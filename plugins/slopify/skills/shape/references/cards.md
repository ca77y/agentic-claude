# Card operations

Read `docs/BOARD.md` for the tracker, its bindings, the card schema, the statuses, and each operation's conditions. Find the exact target card, and use the bound search to find related or duplicate cards.

Prepare content in the board's card shape: problem and outcome, scope and exclusions, observable acceptance criteria, dependencies, and evidence, with assumptions and decisions kept separate. For an update, read the current card first and preserve the fields you aren't changing.

Create or update only when the user asked for that operation and the declaration binds it; otherwise keep the prepared content and report the blocked operation. Create at the declared initial status. Never cross a human gate, change product intent, or rewrite acceptance criteria to fit an implementation. Comments need the user's explicit request.

Return the saved card's identity, or the prepared content and why it wasn't filed.
