# BOAD: Discovering Hierarchical Software Engineering Agents via Bandit Optimization (arXiv 2512.23631v2)

> [!quote] Source
> **URL**: https://arxiv.org/html/2512.23631v2
> **Accessed**: 2026-11-17
> **Method/Context**: Full-text HTML of v2 (Xu et al.). Published 2025-12-29 (v1); v2 dated 2026-01-01. The researcher searched the HTML by keyword and did not read every line. Quotations are marked "quote"; everything else is paraphrase or the scribe's inference.

## Key evidence

- **Tokens, single agent vs orchestrated.** Total tokens per issue (average of input plus output): SWE-bench Verified, SWE-agent 0.92M vs BOAD 0.93M (+0.7%); SWE-bench-Live, 1.49M vs 1.13M (-23.8%). Max input tokens: Verified 34.6k vs 30.5k (-11.6%), Live 49.0k vs 36.7k (-25.0%). Source: sec 5.2 Token Analysis, Table 2. "Surprisingly, the total token count is comparable—and even lower on SWE-bench-live—than in the original SWE-agent. Moreover, BOAD consistently reduces input tokens" (quote). ^e1

- **What is held fixed.** The orchestrator and every sub-agent run on Seed-OSS-36B-Instruct at temperature 0.0, with the SWE-agent scaffold and default tools (edit_anthropic, bash, submit). Caveat: the orchestrator prompt and sub-agent prompts were generated by Claude-4 and tuned on a 12-issue design set, so design and prompts are searched together. Controlled on model and tools, with a prompt-tuning caveat. Source: sec 5.1. "both orchestrator and sub-agents use Seed-OSS-36B-Instruct with temperature 0.0" (quote); "This choice ensures improvements reflect the benefit of orchestration rather than fine-tuning" (quote); "Each sub-agent is ... given access to the same default tools as the orchestrator." (quote) ^e2

- **Success rates (Table 1, Seed-OSS-36B; no sample size or significance given in the table).** SWE-bench Verified / SWE-bench-Live: SWE-agent single agent 49.8 / 12.3; SWE-agent + manual sub-agent 47.4 / 14.0; SWE-agent + evolutionary search 46.0 / 17.0; SWE-agent + BOAD 53.2 / 20.0. The manually designed multi-agent design scored below the single agent on Verified. 53.1 is the Verified score excluding the 12 design-set issues. The Live ablation counts 60/300 (20.0%) for BOAD, so Live has 300 issues. Source: Table 1 and Table 3. The researcher found no significance test in the text searched, and each result appears to be a single run at temperature 0 (inference). ^e3

- **Ablations: coordination design drives the result.** Without sub-agents but with a tuned prompt: 16.3% on Live. Sub-agent count on Live: one scores 49/300, two peak at 60/300 (20.0%), three score 49/300, four 50/300, five 41/300. The authors say larger teams "reduce performance due to communication and coordination overhead" (quote). A generic orchestrator prompt scores 50/300 (16.7%) vs 60/300 (20.0%) with a customized prompt. Source: sec 5.3, Table 3. ^e4

- **Authors' stated limits.** "discovered sub-agents transfer across models only partially and failure cases highlight error propagation when orchestrators unconditionally accept sub-agent outputs" (quote). Only a small open model (36B) was run; evolution on large models is left as future work. Source: Limitations and Future Work. ^e5

## Limitations

- Cost per run and latency per design are not reported for the single-agent vs orchestrated arms in the text searched (keyword search of the full HTML; not every line read).
- One 36B open model only; results may not transfer to frontier models, as the authors say.
- Table 1 gives no sample size or significance test, and results appear to be single runs.
- Prompts and design were tuned together on a 12-issue set, so the gain mixes orchestration with prompt tuning.
- Sub-agent designs were found by search on the same benchmarks family, so the BOAD arm had a tuning advantage the SWE-agent baseline did not (inference).

## Relevance

- A controlled single-agent vs orchestrator-plus-sub-agents comparison on coding tasks that reports tokens: orchestration was token-neutral on Verified and cheaper on Live in this setup (^e1, ^e2).
- Orchestration was not a uniform win: a manual design lost to the single agent on Verified, and more sub-agents lowered success (^e3, ^e4).
- Error propagation from unconditionally accepted sub-agent output is a named failure mode (^e5).
